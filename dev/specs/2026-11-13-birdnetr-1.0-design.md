# birdnetR 1.0 — Design

- **Date:** 2026-11-13
- **Status:** draft, awaiting approval
- **Owner:** Felix Günther
- **Target:** CRAN submission ~2026-11-27, gated on the upstream `birdnet` release that ships the final BirdNET+ V3.0 model

## 1. Intent

BirdNET+ V3.0 was released on 2026-11-13 ([Zenodo 24162518](https://zenodo.org/records/24162518), Apache-2.0, 11,709 species + 16 non-animal classes). birdnetR currently pins the Python package to `birdnet>=0.2.16,<0.3`. Upstream has since moved through 1.0.0 → 1.4.0, which adds the V3.0 models, new backends (`pt`, `onnx`) and makes TensorFlow optional. R users can reach none of this today.

birdnetR 1.0 makes the Python `birdnet` library available from R. It stays a thin wrapper with the same capabilities and output, and it works directly with birdnetTools for post-processing.

A user who installs birdnetR 1.0 can:

- run BirdNET 3.0 (default), BirdNET 2.4, and Perch v2 acoustic models,
- run the geo ("meta") models 3.0 and 2.4,
- get embeddings (`birdnet_encode()`),
- load custom classifiers trained with BirdNET-Analyzer on the 2.4 or 3.0 base,
- optionally run on a GPU (Linux NVIDIA, macOS Apple Silicon, experimental AMD/ROCm),
- hand the results to birdnetTools without renaming columns, once birdnetTools recognises the upstream column names (§6.9).

## 2. Goals, non-goals, anti-goals

**Goals**
- Parity with the Python library's *main calls*: load (official / Perch / custom), predict (acoustic / geo), encode, write results, list models/languages/species.
- Smallest possible default install (ONNX Runtime + LiteRT). Heavy runtimes are installed only when a call needs them.
- A consistent `birdnet_<verb>[_<what>]` public API.
- Users see exactly which model they loaded.

**Non-goals (later)**
- In-memory audio input (`predict_arrays` / `encode_arrays`, issue #52).
- ONNX GPU and any GPU path that `py_require()` can't express (documented as "bring your own environment" instead).
- Interactive model chooser.

**Out**
- Python internals: sessions, `progress_callback`, `on_file_complete`, download-progress hooks.

**Anti-goals** (would make 1.0 a failure even if it "works")
- The default install pulls in TensorFlow or PyTorch.
- birdnetR renames or reshapes upstream output columns, which would break the R ↔ Python parity.
- Loading a model prints so much that loops and knitted reports become unreadable.
- Shipping a GPU path nobody has run.
- Re-implementing in R what upstream already decides, such as which model combinations exist or argument validation, in a way that drifts from upstream.

## 3. Constraints

- **CRAN:** examples that need Python stay in `\dontrun{}`. Tests that need Python/network are gated (existing `BIRDNETR_RUN_INTEGRATION_TESTS`). No interactive prompts. CRAN currently has 0.3.2 and **no reverse dependencies**, so breaking changes have no downstream cost. None of the 1.0-dev names were ever released, so renames need no deprecation cycle.
- **reticulate ≥ 1.46 / uv:** `py_require()` declarations are resolved when Python initializes. Afterwards packages can only be *added*, which activates a layered ephemeral env. Nothing can be removed or swapped, and the Python version can't change. `py_require()` has no effect for users who manage their own Python env.
- **Python version:** keep `>=3.11,<3.14`. The lazily added `[tf]` extra must resolve on the interpreter already chosen, and TensorFlow has no 3.14 wheels.
- **Upstream platform gaps:** LiteRT has no wheels for macOS x86_64 / Windows ARM64. TensorFlow on macOS x86_64 is pinned to 2.16 / Python ≤3.12. Perch can't run on Intel macOS.
- **Upstream starts worker processes with `spawn`** on all platforms (since 1.0.0), and so does `load_custom(check_validity = TRUE)`. This is unverified inside an R-embedded Python on Linux/macOS (see §8, task 1).
- **Timeline:** about 2 weeks, and the final release depends on upstream shipping the final 3.0 model files (prepared in upstream commit `daaf9b8`/#162; pins still on the preview).

## 4. Upstream facts the builder needs (birdnet 1.4.0)

| Install | Enables |
|---|---|
| `birdnet` (base) | acoustic/geo 3.0 on `onnx`; acoustic/geo 2.4 and custom 2.4 TFLite on `tf` with `library = "litert"` |
| `birdnet[tf]` | `tf` with the default `tflite` interpreter, `pb` for everything, Perch v2, Raven exports |
| `birdnet[pt]` | acoustic/geo 3.0 on `pt` |
| `birdnet[and-cuda]` | `[tf]` + CUDA (Linux): GPU for `pb` |

- Official model combinations live in `birdnet.model_loader._OFFICIAL_MODELS`, keyed by `(type, version, backend)`. Each value's `.backends` dict is keyed by the supported precisions.
- Languages: `VALID_MODEL_LANGUAGES_V2_4`, `VALID_MODEL_LANGUAGES_V3_0` (importable from `birdnet`).
- `load(type, version, backend, *, precision, lang, library=...)` has **no defaults** for type/version/backend.
- `load_custom(type, version, backend, model, species_list, *, precision, check_validity, library=, is_raven=)`. `version = "auto"` reads the base version from a TFLite file. `classifier_type` is accepted but ignored.
- `inspect_custom_tflite(model, library=)` returns `CustomTFLiteInfo` (version, mode, n_species, sigmoid-in-model, embeddings, input_samples).
- `load_perch_v2(device = "CPU")`.
- Predict defaults differ per model: Perch has `apply_sigmoid = False`, `sigmoid_sensitivity = None`. The 2.4 and 3.0 models have `True` / `1.0`. New in predict: `apply_softmax`, `segment_size_s` (3.0 only), `device`.
- GPU lookup: `pt` → `torch.cuda` only (ROCm builds of PyTorch expose HIP through `torch.cuda`). `onnx` → `CUDAExecutionProvider` only. `tf`/`pb` → `tf.config.list_physical_devices("GPU")`, which `tensorflow-metal` populates on Apple Silicon.
- Output columns (structured array, data frame, Arrow, CSV):
  - acoustic predict: `input, start_time, end_time, species_name, confidence`
  - geo predict: `species_name, confidence`
  - encode: `input, start_time, end_time, embedding`
  - `species_name` is `"<scientific>_<common>"`. From the next upstream release (#162) underscores *inside* names become spaces, so splitting on the first `_` is safe. `to_csv()` writes times as `"HH:MM:SS.cc"` strings, while the data frame has numeric seconds.
- `BIRDNET_OFFLINE=1` (next upstream release) refuses all downloads.
- `dev/architecture/birdnet-python-architecture.md` describes 0.2.x. Don't rely on it.

## 5. Approaches considered

### 5.1 Python install footprint
- **A. Always `birdnet[tf]`.** Everything works on first use, but every user downloads ~1.5 GB of TensorFlow, including those who only use 3.0.
- **B. Base only. TensorFlow is an explicit opt-in** (e.g. an option set before loading). Small, but Perch fails until the user acts.
- **C. Base only. `[tf]` / `[pt]` are added via `py_require()` the first time a load needs them.** ← **chosen**. Small install, and Perch, `pb` and `pt` still work without a manual step. Risk: an extra added after Python started must be visible to `spawn`ed workers. Task 1 verifies this, and **B is the fallback** if it fails.

### 5.2 Default model for `birdnet_load()`
- **A. 3.0 on `onnx`** (acoustic and geo). ← **chosen**. It is the headline model and runs on the base install on every platform. 1.0 is a breaking release anyway.
- B. 2.4 on `tf`/LiteRT. Same model as 0.x, but it fails out of the box on Intel Macs.
- C. `version` required, as upstream does. Explicit, but every first call needs an extra argument.

### 5.3 GPU
- Full automation of every backend/platform: not possible. `onnxruntime-gpu` must *replace* `onnxruntime` (a dependency of `birdnet`), and `py_require(action = "remove")` only removes our own declarations.
- Docs only: safe, but Linux/Mac users do the env setup by hand.
- **`birdnet_use_gpu()` in the style of keras3's `use_backend()` (declarative, before Python starts), plus a `device` argument, plus a vignette section for everything else.** ← **chosen**. Each branch ships only if it was run on real hardware before release.

### 5.4 Naming
- Bare S3 (`predict()`, `encode()`, `load_*()`): native R feel, but `encode` / `load_*` collide easily and the team prefers a prefix.
- **`birdnet_<verb>[_<what>]`** ← **chosen** (team decision). It mirrors Python (`birdnet.load` → `birdnet_load`) and matches birdnetTools' existing verb-first names. Tab completion on `birdnet_` lists everything.

## 6. Design

### 6.1 Public API

| 1.0 | Replaces (1.0-dev) | Replaces (0.3.2 on CRAN) |
|---|---|---|
| `birdnet_load(type = "acoustic", version = "3.0", backend = NULL, library = NULL, precision = "fp32", language = "en_us")` | `load_birdnet()` | `birdnet_model_tflite()`, `birdnet_model_protobuf()`, `birdnet_model_meta()` |
| `birdnet_load_perch(device = "CPU")` | `load_perch()` | — |
| `birdnet_load_custom(model, species_list, type = "acoustic", version = "auto", backend = "tf", library = NULL, precision = "fp32", check_validity = TRUE, is_raven = NULL)` | `load_custom()` | `birdnet_model_custom()` |
| `birdnet_inspect_custom(model, library = NULL)` | — (new) | — |
| `birdnet_predict(model, ...)` — S3 generic; methods for acoustic and geo models | `predict()` methods | `predict_species_from_audio_file()`, `predict_species_at_location_and_time()` |
| `birdnet_encode(model, files, ...)` — S3 generic; method for acoustic models | `encode()` | — |
| `birdnet_write(x, file, format = NULL, ...)` — predictions **and** encodings | `write_predictions()` | — |
| `birdnet_list_models(compact = FALSE)` | `supported_model_configurations()` | — |
| `birdnet_list_languages(version = "3.0")` | `supported_languages()` | `available_languages()` |
| `birdnet_list_species(model)` | `get_species_list()` | `labels_path()`, `read_labels()` |
| `birdnet_sitrep()` | `birdnet_version()` | — |
| `birdnet_use_gpu(backend = c("pt", "pb"))` | — (new) | — |
| `as.data.frame()`, `print()` S3 methods | unchanged | — |

- The `predict()` and `encode()` S3 methods are **removed**, not aliased, so each call has one name.
- `as.data.frame()` and `print()` stay standard S3. That is how R users expect to convert and print.
- `load_custom()`'s `classifier_type` is removed, since upstream ignores it. `model` and `species_list` move to the front because they are always required.
- Argument order and the remaining argument names follow the current 1.0-dev functions unless stated here.

### 6.2 Python dependency and environment (`.onLoad`)
- `py_require("birdnet>=1.4,<2", python_version = ">=3.11,<3.14")`. When upstream releases the final 3.0 model, raise the lower bound to that release. Keep the existing `BIRDNETR_BIRDNET_VERSION` exact-pin override.
- **Fix:** `.onLoad` currently forces `Sys.setenv(RETICULATE_PYTHON = "managed")` unconditionally. That overrides users who bring their own environment, which the GPU vignette recipe relies on. Set it only when `RETICULATE_PYTHON` is unset.

### 6.3 Lazy extras (approach 5.1 C)
- One internal helper, e.g. `require_birdnet_extra("tf" | "pt")`, calls `py_require()` with the same version spec plus the extra.
- Call it, before calling into Python, in:
  - `birdnet_load_perch()` → `tf`
  - `birdnet_load()` / `birdnet_load_custom()` when `backend == "pb"`, or `backend == "tf"` and the resolved library is `"tflite"` → `tf`
  - `is_raven = TRUE` → `tf`
  - `backend == "pt"` → `pt`
- If Python isn't initialized yet, this is a plain declaration. If it is, reticulate layers a new env (task 1 verifies that workers see it).

### 6.4 Loading defaults, load message, print
- `backend = NULL` resolves from the version: `"3.0"` → `"onnx"`, `"2.4"` → `"tf"`.
- `library = NULL` with `backend = "tf"` resolves to `"litert"` if `ai_edge_litert` is importable, else `"tflite"` (which triggers `[tf]`). This covers Intel macOS and Windows ARM.
- Every successful load emits **one `message()` line**, e.g. `BirdNET acoustic 3.0 · onnx · fp32 · en_us · 11,725 classes`. Perch and custom models get the equivalent, e.g. `Perch v2 · pb · CPU · 14,795 classes`, `Custom acoustic 2.4 (auto) · tf/litert · 34 classes`. Class count = length of the model's species list.
- The **first** load in an R session also emits the BirdNET ASCII logo before that line. Copy `ASCII_LOGO` from BirdNET-Analyzer `birdnet_analyzer/cli.py` (MIT, same team; note the source in a comment; trim trailing whitespace). Use a package-level flag for "already shown".
- Everything goes through `message()`, so `suppressMessages()` silences it. No color, no new dependency.
- `print.birdnet_model()` prints the same one-line description instead of today's raw list dump.

### 6.5 `birdnet_list_models()`
- Derive rows from upstream `_OFFICIAL_MODELS` (single source of truth): `type, version, backend, library, precision`.
- `library` is `litert`/`tflite` for `tf` rows, `NA` otherwise. Upstream refuses `litert` for geo 3.0.
- Add a `needs` column (`base` / `tf` / `pt`) so users can see which choice triggers an install.
- Add a Perch row (loaded with `birdnet_load_perch()`).
- `compact = TRUE` keeps its current meaning.
- Because `_OFFICIAL_MODELS` is private, add an integration test that fails loudly if it disappears or changes shape.

### 6.6 Custom models
- `version = "auto"` by default. For `pb`/Raven the user must pass `"2.4"` or `"3.0"`. Let upstream's error say so.
- `birdnet_inspect_custom()` wraps `inspect_custom_tflite()` and returns a named list of the `CustomTFLiteInfo` fields.
- NEWS must state: **Raven 2.4 scores change.** Upstream fixed a double sigmoid that squeezed scores into 0.5–0.73. Raven label CSVs now yield names without the id column. `encode` is not available for Raven exports.

### 6.7 Predict / encode arguments
- `apply_sigmoid` and `sigmoid_sensitivity` default to `NULL`, which means omitted, so each model's own default applies. This fixes the existing bug where birdnetR forced `apply_sigmoid = TRUE` on Perch, and fixes it for every model at once.
- New, all default `NULL` (omitted): `apply_softmax`, `segment_size_s`, `device` (predict, encode, geo predict where upstream supports it).
- Geo predict also gets `year_round_aggregation = NULL` (upstream: `"max"` or `"average"`, used when `week = NULL`). *(Builder-check call.)*
- Geo 3.0 on `tf` requires TensorFlow 2.18/2.19, but the lazy `[tf]` resolves to the newest TensorFlow, so that combination fails with upstream's `RuntimeError`. Don't work around it: document it, and show it in `birdnet_list_models()`'s `needs` column (e.g. `tf (2.18–2.19)`). *(Builder-check call.)*
- Keep the current R-side validation light. Upstream validates and its errors are good (see the 1.4.0 changelog).
- Update docs that hardcode 2.4 assumptions (e.g. "overlap in [0, 3]").

### 6.8 GPU
- `birdnet_use_gpu(backend = c("pt", "pb"))` must be called **before Python starts**. Error if `reticulate::py_available()` is already `TRUE`. It only declares requirements:
  - Linux + `pt` → `birdnet[pt]`. If `UV_TORCH_BACKEND` is unset, set it to `"auto"` so uv picks a torch build matching the driver. AMD users set `Sys.setenv(UV_TORCH_BACKEND = "rocm6.4")` (or similar) first: **experimental ROCm**.
  - Linux + `pb` → `birdnet[and-cuda]` (NVIDIA driver + CUDA must already be installed).
  - macOS arm64 + `pb` → `birdnet[tf]` + `tensorflow-metal`.
  - Anything else → error pointing to the vignette.
- One backend per call. TensorFlow and PyTorch each pull their own CUDA wheels, which can conflict.
- Then: `birdnet_load(backend = "pt")` / `birdnet_load_perch(device = "GPU")` and `device = "GPU"` in predict/encode.
- Vignette section: the above, plus the "bring your own environment" recipe for ONNX GPU (`virtualenv_create` → remove `onnxruntime` → install `onnxruntime-gpu` → `use_virtualenv()` before first use), plus the caveats (upstream lists macOS ProtoBuf-GPU as unsupported; `tensorflow-metal` lags TensorFlow releases).
- **Ship gate:** each branch ships only if it was run on hardware before release. Any branch that fails its run is removed from the function and described as untested in the vignette. Felix runs:
  - Linux + NVIDIA RTX 3070 → `pt` (CUDA) and `pb` (`and-cuda`)
  - Mac M1 → `pb` + `tensorflow-metal`
  - Linux + AMD Radeon 880M/890M laptop → `pt` via ROCm (experimental; a failure here only drops the ROCm note, not the `pt` branch)

### 6.9 Output and birdnetTools
- birdnetR keeps upstream's column names exactly (§4). `as.data.frame()` output is unchanged.
- File an issue on `birdnet-team/birdnetTools` asking `birdnet_detect_columns()` to recognise birdnetR/Python output:
  - `species_name` → split into scientific / common on the first `_`
  - `input` → file path
  - `start_time` / `end_time` as numeric seconds (data frame) **or** `"HH:MM:SS.cc"` strings (CSV from `birdnet_write()`)
  - geo output has no time/file columns
- **Not gated:** birdnetTools isn't on CRAN, so birdnetR 1.0 doesn't wait for it. Felix proposes the change in birdnetTools (an issue draft exists). Until birdnetTools ships it, birdnetR's docs say the hand-off needs the next birdnetTools version, and show a short rename snippet for older versions.

### 6.10 Documentation
- README, `vignettes/birdnetR.Rmd`, `workflow.Rmd`, `Troubleshoot.Rmd` rewritten for the new names and 3.0 defaults.
- New GPU section (§6.8).
- Model overview: 3.0 / 2.4 / Perch, class counts, licenses of the model files (3.0: Apache-2.0; check the others upstream).
- Troubleshooting:
  - don't wrap birdnet in `parallel`/`future` workers (each worker is a fresh R session without the Python setup, see #56); use `n_workers`
  - `BIRDNET_OFFLINE=1`
  - `birdnet_sitrep()` output to include in bug reports
- NEWS: one 1.0.0 entry, with a migration table from **0.3.2 names** directly to 1.0 names (1.0-dev names were never released).
- `_pkgdown.yml` reference index updated.

### 6.11 `birdnet_sitrep()`
Returns (and prints) the Python version and path, the `birdnet` version, and which runtimes are importable (`onnxruntime`, `ai_edge_litert`, `tensorflow`, `torch`). This replaces `birdnet_version()`.

## 8. Verification

**Task 1: risk check (throwaway, scratchpad, before building on the assumptions):**
- `py_require("birdnet>=1.4,<2")` installs, 3.0 `onnx` `predict` + `encode` run inside R on Linux (spawn workers OK).
- After Python has started, `py_require("birdnet[tf]…")` → `load_perch_v2()` predict works, and the spawned workers can import TensorFlow. **If this fails → approach 5.1 B.**
- `load_custom(..., check_validity = TRUE)` with `dev/rc_20240214/Custom_Classifier.tflite` (2.4) works with `version = "auto"` on LiteRT.
- A custom 3.0 TFLite on the base install: does it need `[tf]`?
- With `RETICULATE_PYTHON` pointing at a user venv, birdnetR uses it and doesn't clobber it.
- `UV_TORCH_BACKEND` changes which torch build reticulate's cached ephemeral env gets. A stale cached env would hide this.

**Automated tests:** existing mocked unit tests renamed and extended (backend/library resolution, lazy-extra triggers, `NULL` omission, load message, print, `birdnet_use_gpu()` platform branches with mocked `Sys.info()`). Integration tests gated as today: 3.0 onnx (acoustic, geo, encode), 2.4 litert, Perch, custom 2.4, `birdnet_list_models()` shape.

**Manual, before release:** GPU branches on the three machines listed in §6.8. ROCm support for the Radeon 880M/890M integrated GPU is limited, so that run may need workarounds.

### 8.1 Task 1 results (2026-11-18)

birdnet 1.4.0, Python 3.12, reticulate 1.46.0, Linux.

- **A PASS.** 3.0 `onnx` predict (45 rows) and encode (20 rows), geo 3.0 predict (464 rows), inside R. Upstream's 3.0 download still has 11,560 classes, i.e. the preview model.
- **B PASS once adapted.** `py_require("birdnet[tf]…")` after Python started is refused by reticulate ("only adding new packages is supported"): `birdnet` is already a requirement, and an extra counts as changing it. Declaring the extra's own package instead works: `py_require("tensorflow>=2.8.0")` after start, then `load_perch_v2()` predicts (60 rows). It works with the default `fork` start method and with `spawn` forced (the macOS/Windows default). A1 also passes under `spawn`. Control (`birdnet[tf]` declared before start): PASS.
- **C PASS.** Custom 2.4 TFLite, `version = "auto"`, LiteRT, `check_validity = TRUE`: resolves to 2.4 and predicts.
- **D PASS.** With `RETICULATE_PYTHON` pointing at a uv venv with birdnet, birdnetR uses that venv. There, `py_require()` after start does nothing and raises no error, so lazy extras can't help. Users install `birdnet[tf]`/`[pt]` into their own venv.
- **E PASS (resolution only).** `UV_TORCH_BACKEND` changes the torch build: cpu → 2.15.0+cpu, cu126 → 2.14.1+cu126, rocm6.4 → 2.9.1+rocm6.4.
- **F not run** (no custom 3.0 TFLite available).
- **Decision: 5.1 C confirmed, adapted.** `require_birdnet_extra()` declares `birdnet[<extra>]` before Python starts (upstream's pins apply) and the extra's own packages after (`tensorflow`, `torch`). Exception: on Intel macOS, `[tf]` pins `tensorflow` 2.16 and `pyarrow<26`. reticulate can't add a pin on the already-installed `pyarrow` once Python is running, so there the helper stops and asks for a restart, with the TensorFlow load as the first birdnetR call. Perch is not supported on Intel macOS anyway.
- Notes for docs: decoding `soundscape.mp3` prints harmless libmpg123 `part2_3_length` errors, and TensorFlow prints CUDA/XLA log lines on CPU-only machines.
